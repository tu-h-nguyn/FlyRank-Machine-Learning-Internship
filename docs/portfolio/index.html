Search-Ranking Refresh Queue

Flagship Paper + code public

An editorial team can review about 50 pages a week out of 18,000. The useful question is not "which pages are bad" but which pages should be opened first — an ordering problem, not a threshold one.

Why it matters
Review time is the constraint. Ordered by the model, roughly 44 of the first 50 pages opened are real decliners, against about 31 for an unordered list — the difference is a week of editorial work spent where it is needed.
Method
Defined the decision, the label and the decision point first · leakage audit that removed every window-spanning column · 24 decision-time features · a transparent rule baseline before any model · logistic regression and random forest · precision@K at the team's real capacity · permutation importance.
Formulation
One 90-day snapshot split into three exact 30-day windows. The label is a >20% fall in impressions in the last window; every feature is knowable at the end of the second. Pages are ranked by predicted probability and scored where the team works — the top 50. P(decline∣x)=σ ⁣(w⊤x+b)precision@K=∣ top-K∩decliners ∣K,K=50\begin{gathered}P(\text{decline}\mid x)=\sigma\!\left(w^{\top}x+b\right)\\[3pt]\text{precision@}K=\frac{\lvert\,\text{top-}K\cap\text{decliners}\,\rvert}{K},\qquad K=50\end{gathered}P(decline∣x)=σ(w⊤x+b)precision@K=K∣top-K∩decliners∣​,K=50​
Experiment
30,000-row anonymised snapshot → 18,010 pages above a 100-impression floor, 30 clients. Rule, logistic regression and random forest scored out-of-fold under GroupKFold(5) by client, so no client is ever in both train and test; stability checked across five client holdouts; a deliberately leaky model kept as a control.
Result
Logistic regression on honest features: PR-AUC 0.718, precision@50 0.88 — against 0.668 / 0.74 for the rule baseline and 0.617 for random ordering, on a 0.62 base rate. The grouped split scored 0.042 lower than a naive random-row split — the split design, not the model, was doing the honest work. The leaky model reached a perfect 1.000 and was discarded.
Limitation
One snapshot, not a time series: nothing tests whether the ranking holds across months. Thirty clients is a small sample — PR-AUC moves between 0.63 and 0.70 depending on which clients are held out. Search position and content freshness had to be dropped because they span the outcome window. No experiment, no control group: this cannot say that refreshing a page recovers its traffic.
My role
Started from FlyRank's internship starter repository — an anonymised dataset, a skeleton script and empty notebooks. The framing, the audit, the features, the models, the evaluation, the 18,010-row action queue and the paper are mine.

Sharp CFL Analysis — FEM for the Wave Equation

Report + code public

Every course quotes Δt ≤ h/c as the stability limit for explicit time-stepping on the wave equation. With a consistent mass matrix that bound is wrong, and a scheme built on it diverges — quietly, because the unstable mode is the one your initial data barely excites.

Why it matters
Explicit schemes are chosen for speed, and their step size is set from exactly this bound. At Δt = 0.9 h/c — inside the textbook limit — the consistent-mass scheme passes 10⁶ before t = 0.4, while the lumped one holds its amplitude within 1% to t = 2.
Method
Closed-form spectrum of the stiffness/mass pair · a necessary and sufficient stability condition · Ritz projection for the convergence proof · Thomas algorithm, O(N) per step · a reproduction harness that recomputes every table from source.
Mathematics
P1 elements in space, leapfrog in time. Experiment
The step size at 0.98 and at 1.02 of the analytic threshold on the same mesh and data; consistent against lumped mass at Δt = 0.9 h/c; convergence over six mesh refinements; the solution eighteen periods on.
Result
Two distinct CFL constants where the literature usually states one. The measured threshold matches the analytic θ* to four significant figures; convergence lands on 2.00 in L² and 1.00 in H¹. All four report tables reproduce digit-for-digit in CI — after the harness caught that the shipped code was missing the 1e-8 mode seeding the report describes.
Limitation
One space dimension, linear elements, a uniform mesh and homogeneous Dirichlet boundaries — the sharp constants are proved for that setting only. The scheme is stable but dispersive: eighteen periods on, the computed wave is visibly out of phase with the exact one.

Finite-Volume Solver for the 1D Euler Equations

Package + tests public

The Euler equations grow shocks, contacts and rarefaction fans out of smooth initial data. A scheme that looks convincing on a smooth problem can be quietly wrong at a discontinuity — so the question is not whether the plot looks right, but what it is being measured against.

Why it matters
Every compressible-flow code rests on how it treats discontinuities. Without an exact reference, a misplaced shock or a smeared contact looks like a plausible curve.
Method
An exact Riemann solver as ground truth, and everything measured against it: four numerical fluxes (Lax–Friedrichs, Rusanov, HLL, HLLC) · MUSCL reconstruction with four TVD limiters and a positivity safeguard · three SSP time integrators · a CLI and a library API.
Mathematics
A conservation law for density, momentum and energy, closed by the ideal-gas law, advanced in conservative form so that shocks move at the right speed: Ut+F(U)x=0,U=(ρ, ρu, E)p=(γ−1)(E−12ρu2)Ui n+1=Ui n−ΔtΔx(Fi+12−Fi−12)\begin{gathered}U_t+F(U)_x=0,\qquad U=(\rho,\ \rho u,\ E)\\[3pt]p=(\gamma-1)\Big(E-\tfrac12\rho u^{2}\Big)\\[3pt]U_i^{\,n+1}=U_i^{\,n}-\frac{\Delta t}{\Delta x}\Big(F_{i+\frac12}-F_{i-\frac12}\Big)\end{gathered}Ut​+F(U)x​=0,U=(ρ, ρu, E)p=(γ−1)(E−21​ρu2)Uin+1​=Uin​−ΔxΔt​(Fi+21​​−Fi−21​​)​
Experiment
Sod's shock tube (N = 200, CFL 0.4, t = 0.2) against the exact solution for every flux; grid convergence up to N = 800; Toro's five benchmarks, including the near-vacuum 123 problem and the Woodward–Colella blast with a 10⁵ pressure ratio.
Result
The L¹ density error falls from 3.274e−02 for Lax–Friedrichs to 4.446e−03 for MUSCL–minmod — 7.4× smaller on the same grid. Observed orders 0.93–0.98 for the first-order schemes and 1.90–2.00 for the second-order ones. All five Toro problems run without tuning. 133 tests, 98% coverage, mypy clean, CI on every push.
Limitation
One space dimension. Classical Lax–Friedrichs is still climbing towards order 1 on these grids, the minmod limiter clips smooth extrema and saturates near order 1.90, and the positivity safeguard drops locally to first order wherever it acts.
My role
The repository is mine — the package, the exact solver, the test suite, the CI and the one-command path to every table and figure. The report behind it is four-person coursework (Nông Thanh Toàn, Nguyễn Hoàng Tú, Lê Minh Tuấn Kiệt, Đặng Kim Bảng), Chuyên đề giải tích số, VNU-HCM University of Science, 2025.

Linear Multistep Methods — Dahlquist, Derived Not Quoted

Library + tests public

Courses state the equivalence theorem — a linear multistep method converges if and only if it is consistent and zero-stable — and the BDF barrier at k ≤ 6, as facts to memorise. Both are checkable by machine, and checking them is more instructive than quoting them.

Why it matters
Every multistep ODE solver in use is a bet that this theorem holds for its coefficients. Order alone guarantees nothing: a method can be consistent to order 3 and still diverge.
Method
A library that hard-codes no conclusions. Given the coefficients it derives the order, the error constant, the roots of the characteristic polynomial, zero-stability and the absolute-stability region — so the textbook claims become test assertions the build has to satisfy.
Mathematics
A method is a pair of polynomials. Experiment
Measured order on eight zero-stable methods; BDF for k = 1 … 7; Method A on y′ = −y with h = 0.1, recomputed from its coefficients for the figure below.

Neural Networks and PINNs for Differential Equations

Thesis + code public

Physics-informed neural networks degrade on problems with a small length scale. The thesis asks why, and at which level: approximation, optimisation, or the stability of the differential problem itself.

Why it matters
PINNs are proposed as general PDE solvers, and their failures are usually reported as anecdotes. Knowing which level fails tells you what to change — the architecture, the optimiser, or the formulation.
Method
Networks studied through derivatives with respect to the input, giving explicit Jacobian and Hessian recurrences; backpropagation and forward/reverse-mode differentiation derived; gradient pathology, spectral bias and a residual-to-error stability bound, each tested by one experiment with a pass/fail criterion written down before it ran.
Mathematics
The loss is a weighted sum of mean-square residuals. Experiment
Six experiments on an 885-line implementation built directly on torch.autograd, no PINN library: ReLU under a second-order operator, the soft boundary constraint, spectral bias, the diffusion equation, Burgers at small viscosity, and the stability bound.

Inexact and Accelerated Proximal Point Algorithms

Report + code public

The accelerated proximal point method assumes each inner subproblem is solved exactly. In practice it never is — so the question is how much inexactness the O(1/k²) rate survives.

Why it matters
Every proximal step is solved approximately, by another algorithm. Güler's 1992 proof of the accelerated rate has a gap, identified by Salzo and Villa: whether acceleration survives depends on the kind of error certificate the inner solver can provide.
Method
The inexact accelerated method against the classical proximal point method under five inner-accuracy schedules, traced against the O(1/k) and O(1/k²) rates, with the convergence bound proved in the report checked numerically at every outer step.
Mathematics
The proximal operator rarely has a closed form. Experiment
A synthetic LASSO (n = 80, m = 30, sparsity 8); five schedules — fixed budgets of 1 and 4 inner steps, log k, √k, and exact solves — against the classical, unaccelerated method, over 121 outer steps.

One synthetic instance at small scale: the experiments illustrate the theorem, they do not benchmark solvers.

Enterprise Hybrid RAG

Report + code public

Answer questions from PDF, DOCX and Markdown with citations that resolve to a page — and know which retriever to trust for which kind of question.

Why it matters
An answer without a checkable source is not usable inside a company, and a system that never abstains will invent one. Keyword questions (a policy code such as HB-7.2) and paraphrased ones fail in opposite retrievers, so no single retriever is safe.
Method
No RAG framework, so every ranking decision is inspectable. BM25 and dense retrieval built from the same chunk list in one pass · reciprocal-rank fusion · cross-encoder reranking · a confidence gate that abstains · citations resolved to the page, invalid ones dropped.
Architecture
Loaders keep page and section → a sentence-aligned chunker → BM25 Okapi and Chroma (384-d cosine, all-MiniLM-L6-v2) → fusion → reranking with ms-marco-MiniLM-L-6-v2 → confidence gate → context builder → LLM → citation resolution. RRF⁡(d)=∑r∈R1k+rank⁡r(d)\operatorname{RRF}(d)=\sum_{r\in\mathcal{R}}\frac{1}{k+\operatorname{rank}_r(d)}RRF(d)=r∈R∑​k+rankr​(d)1​
Experiment
50 questions over 22 documents (77 chunks), four configurations — dense only, BM25 only, fused, fused + reranker — broken down by question type, and regenerated by CI on every pull request.
Result
Recall@1 0.795 for hybrid + reranker against 0.585 dense-only and 0.643 BM25; MRR 0.909. By type, BM25 scores 1.00 on keyword questions and 0.11 on paraphrase, the dense encoder 0.43 and 0.44 — the reranked hybrid holds both ceilings (1.00 and 0.44) and reaches 1.00 on terminology.
Limitation
The corpus is synthetic and small — 22 documents and 43 scored questions — so every comparison is directional. Generation is not measured with a real LLM. The abstention threshold over-refuses 34.9% of answerable questions. Reranking costs about 694 ms per query against 0.75 ms for BM25.

08

AI Quant Trading Research Lab

Code public

Does a leakage-aware machine-learning signal add value out of sample, after trading costs, relative to simple trading rules?

Why it matters
Most backtests that look profitable leak — shuffled splits, features that peek at the future, costs left out. A harness built so that its answer is allowed to be "no" is worth more than one that always says yes.
Method
Chronological walk-forward refits from independent estimator clones, with an embargo for forward-horizon labels · features from current and past data only · buy-and-hold, momentum and moving-average baselines against logistic regression and XGBoost · costs charged on turnover · moving-block bootstrap for dependent daily returns.
Architecture
Market data → features → baseline and ML signals → walk-forward out-of-sample → portfolio (long-only minimum-variance and risk-parity weights from trailing observations, lagged before returns apply; volatility targeting; drawdown guardrails) → costs and turnover → metrics → bootstrap → report, with each run's configuration and source commit recorded.
Experiment
The flagship study runs the same experiment on SPY, QQQ, IWM, TLT and GLD. AUC is reported as a predictive diagnostic; trading metrics come from a separate cost-aware backtest; the signal threshold is fixed from configuration and never tuned on the out-of-sample period.
Result
A research harness, not a strategy. No returns are quoted here: none are committed to the repository — its research workflow regenerates the report, and an ML signal that loses to a baseline counts as a valid result.
Limitation
Historical simulation only: execution slippage, liquidity, borrow costs, corporate actions and regime shifts can change live outcomes. Five ETFs, daily data. Research and educational software, not investment advice.
Python · pandas · scikit-learn · XGBoost · pytest · ruff · GitHub Actions

03 Method

How I Approach an ML Problem

This is the order I actually work in. It is also the order in which the capstone above was built, and why its honest score is lower than its leaky one.

01Define the decision first. What does someone do differently because of the output? That fixes the label, the grain and the evaluation metric — before any modelling.
02Audit the data for leakage. Every feature gets checked against the decision point. Anything that spans the outcome window is dropped, however predictive it looks.
03Build a transparent baseline. A rule or a simple model, scored the same way. If the model cannot beat it, the model is not the answer.
04Experiment systematically. One change at a time, a fixed seed, and the same split for every candidate so the comparison means something.
05Compare, then attack the result. Check stability across holdouts, inspect what the model leans on, and look for the split design that would make the number collapse.
06Write down what did not work. The failures and limitations go in the report next to the results — they are what makes the results usable.
